# S5.5 retrospective — teacher print migration (reviewed 2026-08-06)

**Scope:** slice S5.5 of the components-as-data rewrite (2026-08-03/04: answer-key
extraction `3837f62`, key on paper `843a982`, print shuffles `a3a3ada`, preview
`1b7b75f`, route rebuild `ba08777`, foldable `37d64c9`, answer-key parity
`f756e96`, renderer eviction `1319130`, versions + lockChoiceOrder `eea7c75`,
baselines `4743c66`, gate retirement `29ea4f5`, DECISIONS `c68c443`; plus the
never-identity shuffle deploy), reviewed after S6–S8 and before S9. **Evidence
base:** commit history, the 23-ruling eng-review record, and a fresh-context
survey of the print system's current state. An independent audit pass is expected
to append below.

## Verdict in one line

S5.5's *migration* is complete and clean — the renderer is out of the app
entirely, the answer key is derived-not-stored, and every ruling that was
overturned in-flight got its reasoning written down — but the slice's
*retirement commit* (`29ea4f5`) quietly invalidated two containment plans that
its own comments still claim are in force: the glossary's two copies are no
longer held equal by anything, and the foldable still carries ~55 lines of CSS
targeting a renderer vocabulary that no longer flows through it.

## Costs already paid (lessons banked, no action needed)

1. **The ruled default would have printed answer keys.** The review's original
   "base print skips shuffles" call was caught by the outside voice *before
   build* (D15A, its strongest finding): an unshuffled ordering block on paper
   IS the answer key. The fix — `print.shuffled` on the PrintSpec, outside the
   sanitize object so `SANITIZER_REV` doesn't move — came with the generalized
   guard (every serve-shuffled field must be print-shuffled) so the next block
   type cannot repeat the defect.
2. **The viewer's shuffle could deal the identity back** — a fair shuffle
   returns the authored order 1/n! of the time, and ordering blocks allow two
   items, so one student in two could be served a pre-solved question. The
   renderer had always guaranteed never-identity; the viewer gained it
   (`a3a3ada`), pinned across sizes 2–8 × 200 seeds. The deploy note is the
   model: both Edge functions read the shuffle, so they shipped **56 seconds
   apart** — "order does not matter; the gap between them does," with the
   bounded-disagreement window reasoned rather than assumed.
3. **The baselines were generated three times, and the two discarded sets paid
   for themselves**: run 1 pinned a *blank* math block (the harness emulated
   print media without print mode — a hybrid where both renderers hide); fixing
   that surfaced a KaTeX error **that had been printing on real worksheets
   since S3** (`\square` substituted into `\placeholder[g1]{}x` glues into
   `\squarex`, red error text); fixing that surfaced S5.5's own preview CSS
   outranking the print block *inside* `@media print` (0,2,0 vs 0,1,0) —
   closed structurally with `:where()` so preview selectors have zero
   specificity by construction. None of the three was reachable by a rules
   assertion; this is what the screenshot layer exists for.
4. **The renderer's answer key never filled math gaps** — `renderMathBlock` was
   called without `showAnswers`, so gap-bearing equations printed an empty key.
   Found by T1's extraction work, recorded as a named viewer-only improvement.
5. **`savePrint` could destroy concurrent editor work** (D20A): it wrote back
   the whole document this tab loaded, so a teacher with the editor open
   elsewhere lost work by nudging a margin. Now re-fetches and merges only
   `meta.print`.
6. **The foldable's browser pass found two category errors**: a panel is not a
   *phone* (the 480px breakpoint fired in a 4-inch panel and flattened an
   authored 2:1 to a stack — tracks computed `2fr 1fr` while the row computed
   `display:block`), and a panel is not a *screen* (panels render in screen
   media, so dark-mode machines produced dark sheets). Both fixed; see finding
   9 for what didn't come with them.
7. **The font id→family map existed in three copies** (renderer, viewer, app) —
   D18A consolidated labels/families/menu-order into `@activity/schema/fonts`,
   with fallback *stacks* deliberately per-surface. A menu entry silently
   rendering as the default matters most when the menu exists so a teacher can
   pick Atkinson Hyperlegible for a specific child.

## Latent costs — what will bite future developers

8. **The glossary's two copies are unguarded, and the code says otherwise.**
   `print/definitions.ts` was ported-not-imported with a written containment
   plan: "two copies exist only until [the renderer dies at S5.5], and the
   parity gate's document fixture holds them equal meanwhile." Both halves of
   that sentence are now false — the renderer lives until S9
   (`publish-activity` still calls it), and the cross-surface gate retired in
   `29ea4f5`. Anyone reading the file today is told the drift is contained; it
   is not. This is the sharpest instance yet of a lesson the repo keeps paying
   for: **a containment plan that names a guard must be revisited when the
   guard retires.**
9. **The foldable's guarantees are browser-verified-once, unguarded.** The
   480px counter-override and the light-theme pins live in `foldable/styles.ts`
   with "caught by driving the dev bench in a browser" as their only evidence;
   `styles.ts` and `render.ts` have no test file, and no e2e drives the
   foldable (`playwright test print-` matches none of it). A viewer.css
   breakpoint change silently flattens a teacher's printed 2:1 split and
   nothing goes red. The same file carries **~55 lines of dead CSS** targeting
   the renderer's class vocabulary (`.js-checkpoint-btn`, `.blank-wrapper`, …)
   under a header describing a pipeline (`render.ts` injecting renderer styles)
   that no longer runs — dead rather than wrong, which is why it survived.
10. **`print.answerKeyVariant` is declaration-only and now disagrees with the
    real coverage map.** Set on 7 registry types, read by no product code, and
    pinned by a test against "the renderer showAnswers set" — a surface that no
    longer exists in the app — while `ANSWER_KEY_COVERAGE` (the map that
    actually gates) includes two types `answerKeyVariant` omits. Two overlapping
    declarations of "which types have a key," disagreeing, one bonded to a
    ghost.
11. **The retirement left a trail of false prose**: `printExpectations.ts` still
    says "on both surfaces" in four places; the viewer barrel still describes "a
    parity gate on BOTH surfaces"; `viewer.css` names the renamed
    `print-parity.e2e.ts`; and the *viewer's* eslint config justifies its
    src-only scope by exempting "the contact-sheet generator" — deleted in the
    same commit that widened the *app's* guard to whole-package. None affects
    behavior; all misleads the next reader about what is guarded.
12. **`DefinitionGlossary.tsx` carries five `as never` casts in 160 lines**
    (including one double cast) — the densest concession cluster in the print
    code, at the same grading↔graph-kit-shaped seam the S0 audit flagged.
13. **The contact-sheet sign-off's physical evidence is one `git clean` from
    gone.** The 46 PNGs (23 renderer-side) that the whole retirement's
    human-judged leg rests on live gitignored in the working tree; the generator
    that could recreate them is deleted, and the renderer half could only ever
    be regenerated while the renderer remains reachable (until S9). The
    sign-off is *recorded* in HISTORY — but the artifact itself has no durable
    home.

**Opportunistic:**

   print lanes.
7. Ask the author where the contact-sheet PNGs should durably live (a release

   can't decide this one.

**Policy (decide deliberately, not by accident):**

8. **Retiring a guard requires auditing every comment that cites it.** The
   glossary plan, the eslint justification, and the "both surfaces" prose all
   rotted in one commit because the retirement grep'd for code, not claims.
9. **"Ported, not imported" needs a bond with a longer lifetime than the
   port's timeline assumption** — the S4-6 posture (two copies held equal by a
   gate) is only sound while the gate outlives both copies.

## What held up (no apology needed)

**The eviction is complete and stricter than its birth commit**: zero renderer
imports anywhere in app or viewer (product *and* test code — the last e2e
importer died with the contact-sheet generator), the package gone from app's
dependencies entirely, and the app's lint guard widened to the whole package.
**The answer-key design**: derived at render time from the order each render
draws — never stored — which is what keeps one canonical key correct for every
shuffled version; `ANSWER_KEY_COVERAGE` carries anti-vacuity guards (every
declared route must actually produce a key from fixtures; a `children` claim
must produce `{}` on the container). **The bundle-absence guard is
symbol-based because the size guard was proven insufficient by deliberate
experiment** — leaking the module grew the read bundle to 987 KiB, comfortably
under the 1500 ceiling; the retro confirms the committed bundle carries zero
answer-key symbols today. **The `lockChoiceOrder` chain** runs schema → registry
(`shuffleLockedBy`, keeping the transform a generic walk) → editor toggle →
serialize both ways → guard, additive at every layer. **The D24-C preview guard
held** — the CSS duplication it polices is real and unavoidable, and its
value-equality test exists because the presence-only version shipped the header
bug. **The cross-surface answer-key gate ran green before the eviction made it
impossible** (D12A — comparing *meaning* through each surface's own bank, never
letters), and its coverage survived retirement as viewer-only pins with the
extracted key as oracle. **T8-before-T7 was re-sequenced by the author and
D9A's constraint held in substance** — eviction scoped to product code so the
contact sheet stayed generable until its last-possible read, which happened and
was recorded. And **all four TODOS entries from these slices are live, honestly
scoped, with triggers and start-points** — the anti-pattern of S1's promise rot,
done right.
